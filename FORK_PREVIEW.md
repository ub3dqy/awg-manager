# Пробная версия для KN-2311

Это исходный код открытого форка Dima Mak / ub3dqy под MIT. Первая версия
с диагностикой сервисов — `2.19.23+ub3dqy.1`, архитектура `mipsel-3.4`.
Совместимость с KN-2311 и KeeneticOS 5.1.8 ещё должна быть проверена на устройстве.
Успешная сборка и проверка архива не означают, что испытание роутером пройдено.
Вспомогательные программы, модули и сторонние библиотеки сохраняют свои
лицензии; лицензия форка их не заменяет.

## Что находится в пакете

Основой служит официальный пакет `hoaxisr/awg-manager` версии 2.19.23.
Сборщик требует его SHA256, сверяет имя пакета, архитектуру и версию модулей.
Он сохраняет вспомогательную программу `awg`, модули, хуки событий и установочные
сценарии исходного пакета. Заменяется только сам демон AWG Manager; также
добавляются лицензия MIT, этот документ и `BUILD-INFO.json` с происхождением сборки.

Исходный пакет для KN-2311:
`https://github.com/hoaxisr/awg-manager/releases/download/v2.19.23/awg-manager_2.19.23_mipsel-3.4-kn.ipk`

Опубликованный GitHub SHA256 этого файла:
`bfd58460ab2fd9b258a112cc5a1fdf9ddaa5483c81e6b3348acb8ba34e38029f`.
Сверка суммы проверяет целостность относительно опубликованных метаданных;
это не отдельная цифровая подпись разработчика.

Пример повторной сборки после сборки интерфейса и демона для MIPS:

```sh
python3 tools/fork_preview.py \
  --base-ipk awg-manager_2.19.23_mipsel-3.4-kn.ipk \
  --base-sha256 bfd58460ab2fd9b258a112cc5a1fdf9ddaa5483c81e6b3348acb8ba34e38029f \
  --binary build/bin/awg-manager \
  --version 2.19.23+ub3dqy.1 --arch mipsel-3.4 \
  --source-commit "$(git rev-parse HEAD)" --kmod-version 3.1.20260906 \
  --output dist/awg-manager_2.19.23+ub3dqy.1_mipsel-3.4-kn.ipk
```

Демон нужно собирать из чистого состояния указанного коммита, со встроенным
интерфейсом и значениями `main.version=2.19.23+ub3dqy.1`,
`main.buildArch=mipsel-3.4`. Сборщик сам не скачивает и не запускает чужие файлы,
не устанавливает пакет и не выполняет его хуки. Повторная упаковка одинаковых
входных файлов в одинаковом окружении даёт одинаковый архив. Исходные файлы
не перезаписываются.

## Обновления

В пробной сборке проверка и установка обновлений самого AWG Manager с сервера
исходного проекта отключены на уровне программы. Ручной запрос, расписание и
старый сохранённый адрес пакета не обходят это ограничение. Кнопка обновления
заменяется ссылкой на форк; статистика проверки обновлений не отправляется.
Настройки пользователя при этом не переписываются.

Это правило относится к самому AWG Manager. Управляемый sing-box и другие
компоненты сохраняют собственные механизмы загрузки. Обычный `opkg upgrade`
также работает независимо от встроенного обновления: прежний репозиторий opkg
может предложить оригинальную версию поверх форка. До рабочего выпуска нужно
отдельно согласовать источники opkg и канал обновления форка.

## Порядок первого испытания и возврата

Установка на рабочий роутер требует отдельного разрешения владельца. Запуск
полного AWG Manager нельзя считать только чтением: при старте существующие
службы могут восстанавливать маршруты и правила по сохранённым настройкам.

Перед установкой нужны:

1. Чтение точной модели, KeeneticOS, архитектуры Entware, установленной версии
   AWG Manager и свободного места. Пакет для другой архитектуры не использовать.
2. Приватная резервная копия настроек и файлов AWG Manager с ограниченными
   правами доступа. Она содержит ключи, её нельзя размещать в репозитории.
3. Точный прежний установочный пакет, его контрольная сумма и доступный путь
   управления роутером на случай недоступности панели AWG Manager. Если прежний
   пакет получить нельзя, испытание откладывается.
4. Согласованное окно перезапуска панели и конкретный план восстановления.

Для возврата требуется повторная установка именно сохранённого прежнего IPK
с разрешённым понижением версии. `opkg remove awg-manager` для возврата
не применять: удаление запускает очистку туннелей и правил. Если новая версия
успела изменить формат данных, дополнительно восстанавливается приватная копия
каталога настроек при остановленном демоне. Это отдельная операция; одного
старого исполняемого файла недостаточно для обещания полного возврата.

После разрешённой установки проверяют запуск панели, сохранность туннелей,
показатели устройства, диагностику DNS, наблюдаемые соединения, отмену проверки
и выгрузку отчёта. Изменение DNS, маршрутов, LTE, профилей VPN и камер в это
испытание не входит. Подтверждённое испытание и результаты возврата записываются
отдельно; до этого пакет остаётся кандидатом для проверки.
